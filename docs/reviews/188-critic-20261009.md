## 2. Semantics of MemVfs::fallocate against Linux fallocate(2)

Verified by reading `crates/cowfs-vfs-test/src/memvfs/vfs_impl.rs` lines 394-441 and `Pages::punch`.
- Allocate: size becomes max(size, offset+len), bytes kept, new bytes zero. Correct.
- KeepSize: no data or size change. Correct. Only ctime is bumped (documented, not asserted).
- PunchHole: zeroes the in-file part only, never changes size (the `KEEP_SIZE` pairing is encoded in the enum, so the kernel rule "punch requires keep size" cannot be violated). Correct.
- ZeroRange extends to max(size, end); ZeroRangeKeepSize does not. Correct and matches Linux's two different rows.
- `len == 0` gives InvalidArgument. Overflow of offset+len, or end beyond 2^42, gives NoSpace. Linux gives EFBIG. This is a documented, intentional match with `write`/`setattr` until the EFBIG builder lands `FileTooBig`.
- Directory gives IsDir (matches modern kernels); symlink and any non-file give InvalidArgument. Linux returns ENODEV for non-regular files and ESPIPE for FIFOs. Documented for symlink only; see note N3.
- Unsupported kernel combos (COLLAPSE, INSERT, UNSHARE, PUNCH without KEEP) cannot be expressed in `FallocMode`; the wildcard arm returns NotSupported for future variants. The mask validation is slice C (FUSE adapter) and the doc says so.
- Timestamps: content-changing modes call `touch_data` (mtime and ctime); growth also touches mtime; otherwise ctime only. Matches the doc contract.
- Read-only: MemVfs has no read-only mode, so nothing to enforce; the doc assigns EROFS to the Core snapshot view in slice B.
- Snapshot and clone views: not applicable in MemVfs; slice B owns the snapshot-unchanged test. Not verifiable in this slice.
- Order of checks: the kind check precedes the `len == 0` check, so a directory with len 0 gives IsDir where Linux order is unverified here. Unverified, low value.
- Atomicity: one coarse MemVfs lock; the doc states this honestly and defers the interleaving test to Core.

Strength by check:
- punch: asserts size, full content against a byte model across four ranges including partial, past-end and wholly-past-end, plus blocks drop. A wrong impl that writes zeros without freeing pages fails only the blocks assertion, which is weak but present.

- times: asserts mtime and ctime strictly increase for the three content-changing modes. Would fail a wrong impl that skips the bump.
