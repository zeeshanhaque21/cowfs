## Non-blocking findings

- `gc.dry_run.no_pack_change_negative_control` (`scripts/verify-gc-daemon.py:1159`) only re-reads the hash and checks stability. It is not a negative control. The real mutation control is `reclaim.dry_run_mutation_detected`, and it adds a new 1-byte file rather than changing an existing byte (my same-size control shows that case is also detected). Rename the former, correct the doc wording.
- Early-failure leak, reproduced: `main()` creates `/private/tmp/cowfs-gc-e2e-<pid>/` before `selftest()` and removes it only in a later `finally`. The missing-BLAKE3 run left `/private/tmp/cowfs-gc-e2e-54360/` (no sockets, two probe files). I verified it was my run's pid and removed it. A failing selftest therefore leaves a persistent `/tmp` directory.
- `production_build_head` is `git log -1 -- crates` from whatever repo contains the script. It is a proxy for binary provenance, not proof. The harness does not bind the binary hashes to the `crates/` tree. In an archive nested under the repo it resolves to `''` (as in the builder's clean-checkout record) and `harness_head` reads the parent repo, not the archive. The doc calls it "best available signal"; keep that wording.
- Two records are still bare booleans (`selftest.state_hash_stable`, `selftest.state_hash_detects_change`) and `cancel.daemon_survives`. Acceptable for self-tests.
- Duplicate `gc.dry_run` record in the single-pack phase (the dry run is issued twice). Harmless.
- `docs/v1-daemon.md` correction is accurate: one table row and one paragraph changed, 13 lines, and PR #76's `ea95894` really did leave it stale. The PR body now says so correctly.
