## (2) Lazy closure
`log_data` takes `impl FnOnce() -> LogOp`.
With the feature on and no log, cost is one thread-local access plus a RefCell borrow per write, negligible next to a write syscall.
Without the feature `log_data` is an empty fn and the closure is never built, so `name(path)` and `to_vec()` are both lazy and gone in a normal build.
Entry order is unchanged: closures run at the same call sites, one push per call.
The model tests (crash, round3, round4, compact) pass.

## (3) Seam script
Release profile has `debug = "line-tables-only"` and no strip, so names stay in the binary.

## (4) Measurement
Allocs delta 9474 to 7418 is 2056, matches the claim.
Bytes delta 268,510,336 matches 806,780,755 minus 538,270,419. Reduction is 33.3 percent.
The explanation "256 MiB plus 2048 names" does not fit the alloc count: 2048 names plus 2048 copies would be 4096 allocs, not 2056.
2056 = 2 allocs times 1028 write_at calls (1024 puts plus a few creates and header writes).
The 74,880 bytes above 256 MiB would then be about 73 bytes per write: name plus record framing.
That is my arithmetic, not run. The totals are exact, the breakdown text is loose.
The measurement test is built under the self dev-dependency, so the feature is ON in both before and after runs.
It measures the runtime-lazy part only.
The compile-out saving in a real daemon is covered by the seam script, not by this number.
Labelling of the noisy before-runs (740 to 1392 MiB/s) and "indicative only" for throughput is honest.
