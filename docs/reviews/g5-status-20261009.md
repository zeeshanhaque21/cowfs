Issue: 101.
Harness: PR 100 (`bench/xfstests_gate.py`).
Host: the cachyos box, kernel 7.2.8, x86_64, under `/mnt/docs/Projects/cowfs-g5`.

## Verdict

The #101 build blocker is removed.
The gate harness itself still cannot produce a g5 receipt, for three new reasons found below.
A differential run was done by hand with the suite's own `check`.
That run is diagnostic evidence, not a gate PASS.
g5 stays open.

## What the harness measures and the bar

The gate runs a reviewed set of xfstests generic cases through the suite's own `check` on two arms.
The reviewed set is 6 ids, pinned by sha256 in `bench/xfstests-allowlist.txt`.
The native arm is a directory on a native filesystem.
The cowfs arm is a directory on a cowfs FUSE mount.
The bar "no worse than native" means every case that passes on the native arm passes on the cowfs arm, with a positive receipt.
A skip or a refusal on either arm is never counted as a pass.

## What was proven before

PR 100 merged the harness with 162 unit tests, forged-pin controls, process-ownership controls and an arm-placement control (22/22 on the Pi).
On the Pi no case ever ran, because `ltp/fsstress`, `ltp/fsx` and `tests/generic/group.list` were absent.
The `check` path of the gate therefore never ran end to end anywhere before today.

## Blocker 1, removed: the build

Issue 101 said the host could not build the helpers unprivileged.
On the cachyos box autoconf, automake, libtool, m4, gcc and make are installed.
An unprivileged `make -k -j4` at the pinned tree (`3e1ee800e52a0f53d7d9a7809be1ffc80ec1788f`) produced `ltp/fsstress`, `ltp/fsx`, `include/builddefs` and `tests/generic/group.list`.
No root was needed for the build.
The tree stays clean for the gate (`git status --porcelain` empty, build output is ignored).
`xfstests_gate.py preflight` now reports all 11 gate entries present.
`src/locktest` fails to compile against kernel 7.2 headers (`struct delegation` has no member `d_type`).
Cases that need it are skipped as `not built` (generic/786 and 787) or fail on both arms (generic/131, "Server died abnormally").

## Blockers 2 to 4, new: the harness cannot drive the pinned suite

1. `check` refuses to run unprivileged: `check: QA must be run as root`.
   Preflight printed an empty `REASON:` with rc 1, because check's stderr is not surfaced.
   That is a small harness defect: the reason must name the root refusal.
2. `arm_env` sets `TEST_DEV` to a directory and `FSTYP` to empty.
   The pinned `common/config` rejects that: `TEST_DEV (...) is not a block device or a network filesystem`.
3. `common/rc _check_mounted_on` needs `TEST_DIR` to be the exact mount target of `TEST_DEV`.
   The gate uses a per-case subdirectory, so it cannot satisfy that.
4. The cowfs mount root is a read-only namespace of snapshots.
   A write there fails with `Read-only file system`, and generic/005 on the mount root fails for that reason.
   The writable tree is a snapshot directory, and every cowfs mount has fsname `cowfs`.
   So `findmnt -S cowfs` is ambiguous whenever a second cowfs mount exists.
   xfstests also cycles the mount (`_test_cycle_mount`) in many cases.
   cowfs has no `mount.fuse.cowfs` helper, so a case that unmounts its TEST_DIR cannot get it back.

Required shape for a real gate: run as root.
The native arm is a loop-mounted block device (`FSTYP=ext4 TEST_DEV=/dev/loopN TEST_DIR=<its mount>`).
The cowfs arm is a writable snapshot that is itself the TEST_DIR mount target, with a unique source.
Each case gets its own `check` invocation, so a case that destroys its mount only fails itself.
That is a redesign of the arm model, not a small fix, so it is not done here.

## The diagnostic differential (hand-run, not the gate)

Method, all as root through `sudo -S` with the password on stdin:

- Native arm: a 4 GiB sparse image, `losetup`, `mkfs.ext4`, mounted.
  `FSTYP=ext4 TEST_DEV=/dev/loop0`.
- cowfs arm: the daemon ran as root with `--backend core`.
  A fresh empty snapshot per case was bind-mounted in a private mount namespace.
  The main mount was lazily detached in that namespace only, so that `findmnt -S cowfs` names one mount.
  `FSTYP=fuse TEST_DEV=cowfs`.
  Host mounts were untouched.
- `SCRATCH_DEV` and `SCRATCH_MNT` were empty on both arms, so scratch cases are out.
- The list is the gate classifier's SAFE (6) + NEEDS_HELPER (106) + UNREAD_SOURCE (43), which is 155 generic cases.
  That is broader than the 6 reviewed ids and its sources were not reviewed, so it is a diagnostic list only.
- Native ran as one batch `check` over 155 cases, in 13 minutes.
  cowfs ran one `check` per case, isolated, in about 40 minutes on a debug daemon build.
- A first cowfs batch run was discarded.
  Its first `could not mount cowfs` was generic/072, and from there most cases failed on the mount-cycling artifact above.
  That is not a cowfs result.

Validity checks that were run:

- The 6 reviewed ids (005, 236, 245, 309, 360, 755): native `Passed all 6 tests`, cowfs `Passed all 6 tests`.
  Neither had a `Not run`, check's `Ran:` line named all six, and the `FSTYP` header was correct per arm.
- Negative control: generic/005 on the read-only cowfs mount root fails with a real output mismatch.
  So the receipt does distinguish pass from fail.
- Counts over 155 cases: native 127 pass, 26 not run, 2 fail (131, 473).
  cowfs 76 pass, 69 not run, 10 fail.
- 76 cases pass on both arms.

### Native passes, cowfs skipped by the suite (42)

These are not failures, and they are not passes either.
`xfs_io` `fpunch`, `fzero`, `falloc`, `fcollapse` and `fiemap` fail on cowfs.
That covers 008 009 012 016 021 022 058 060 061 063 072 092 094 213 228 255 286 315 316 349 350 351 404 420 436 445 469 539 568 586 742.
`docs/fallocate-103.md` (issue 103) records that the FUSE adapter answers `ENOTSUP` to every fallocate mode.
Also skipped: renameat2 unsupported (078), O_TMPFILE (389), chattr flags (424 545 553 555), inode creation time (528).
Block-device assumptions that do not apply to FUSE: 114 240 418 538.

### Native passes, cowfs fails (9), with the exact assertion

- generic/025 (renameat2 with `RENAME_EXCHANGE`): `samedir regu/regu -> Operation not supported` where native prints `regu/regu.`.
  The same happens for regu/symb, regu/dire and regu/tree.
  Cowfs-specific.
  generic/023 and 024 (renameat2 without exchange) pass.
- generic/285 and generic/448: `seek sanity check failed!` (SEEK_HOLE and SEEK_DATA).
  Cowfs-specific.
- generic/426 and generic/467: `open_by_handle(.../file000000) returned 116 incorrectly on a linked file!` for every file (ESTALE, no file handle support).
  Cowfs-specific.
- generic/087 and generic/088: `access(TEST_DIR/t_access, R_OK) returns -1`, and `a 600 file owned by (99/99) as user/group(99/99) FAIL`.
  Probable setup artifact, unverified: uid 99 is not the mounter and the mount has no `allow_other`.
- generic/074 and generic/127: timed out at the 300 s cap on the debug build (native 34 s and 84 s).
  On a release build both pass, in 58 s and 290 s.
  That is a performance gap of about 1.7x and 3.5x, not a failure.

On the release build 025, 285 and 426 fail again with byte-identical `.out.bad` (285 differs only in a path).

Both-arm failures: generic/131 fails on native and cowfs alike, and uses `src/locktest`, which did not build.
It is a build artifact, not a cowfs regression.
generic/473 fails on native (a data extent mismatch) and is skipped on cowfs.

## Known and by-design

Searched `docs`, `bench` and `crates` (outside `docs/reviews`) for by-design, non-goal, RENAME_EXCHANGE, SEEK_HOLE, open_by_handle, O_TMPFILE and fallocate.
Only fallocate has a record: `docs/fallocate-103.md` (issue 103, `ENOTSUP`, a known gap).
No by-design list exists for rename exchange, seek-hole, file handles or O_TMPFILE.
Whether those are intended v1 gaps is a decision for Zee.
Block-device skips (114 240 418 538) follow from FUSE not being a block filesystem.
