## 2. Foreign-CPU rule

- Own tree is computed at every sample by a ppid walk from the roots [driver pid, daemon pid] over a fresh `ps -A -o pid=,ppid=,pcpu=,comm=` (foreign_cpu). Classification is by pid ancestry, not by command name.
- Our build cannot be misclassified as foreign while it is attached: gates.py is a child of the driver, cargo/rustc/git are its descendants, the `ps` and `top` helpers are children of the driver.
- The daemon is spawned directly with Popen, no daemonize, so its pid is the root and stays valid.
- A heavy foreign process cannot be mistaken for ours by name. Only the INDUCED set is excluded by name, and only from the gate (see below).
- Orphans: a descendant that is reparented to launchd (pid 1) after its parent exits is counted as foreign. That fails safe (false INVALID, for example a daemonizing sccache server), never a false PASS. Non-blocking.
- pcpu is a decaying average on macOS. It is not converted to instantaneous CPU. This is handled by comparing the same metric in the baseline and the arm and by the 50 point margin, and the code docstring says it is a heuristic. A burst shorter than the 5 s period can be missed. Acceptable for a chosen-margin check, and the native-native 10 percent noise check backstops asymmetric disturbance.
- Short arms: one sample at the start, one at the end, one per 5 s in between, so n >= 2 even for reps=1. With n < 20 the p95 index equals the max, so a short arm is judged on its worst sample. That is strict, not weak.
- Long arms: p95 permits up to 5 percent of samples to exceed the limit. A single heavy burst of under 5 percent of the arm passes the gate. `max` and `top3_at_peak` are recorded, so it is visible in verdict.json but not gated. Non-blocking, noted.
- Limit derivation: baseline p95 + 50, where the baseline is measured in this run over a 300 s window (refused below 300 for a gate run). A baseline of 0 gives limit 50, which is a real bar, not a degenerate one. A baseline above 100 is refused (FOREIGN_BASE_CAP), so the limit is at most 150.
- Enforcement is for the whole of every arm (sampler thread runs from before gates.py to after it). The check is post hoc: a breach marks the run INVALID and stops the remaining arms; it does not kill the running arm. The builder claim "a 500-point load stops the arm" means stops the run after that arm; there is no mid-arm kill. The doc wording at line 108 matches the code.
- Between arms, load1, idle and foreign-process-name checks run (Quiet.check), not the CPU rule. That is as the doc says.
- INDUCED by name: yes, a process whose basename is `mds`, `kernel_task`, `fseventsd` and so on is exempt from the gate, including a user binary with that name. This is not adversarially safe, and the doc says the set is chosen. Gating it was assessed: kernel_task legitimately includes the mount's NFS client work and the native arm's APFS I/O, so a baseline-relative gate on it would false-INVALID. The honest middle path is what the builder did: record `induced_max` per arm, and compare native and cowfs arms by eye or in a later round. Non-blocking.
- Sampler-thread failure: if `ps` raises in the thread, the thread dies silently and only the finish() sample remains (n = 1), which passes. Very unlikely. Non-blocking.

## 3. Cool-down

- 7 polls, 10 s apart, all <= cap, spread < 0.5, timeout 600 s (the check runs before the timeout test, so a plateau reached on the last poll still counts). It cannot hang: it is bounded by the clock and returns (False, last) which becomes INVALID with a reason.
- Consistency with the baseline rule: both use args.load_cap (4.0); the baseline requires p95 load1 <= cap. No contradiction.
- False-settle: load1 is itself a 1 minute average, so a 60 s window can show a spread under 0.5 while still decaying near the cap (for example 4.0 down to 3.6). The baseline would then include some residual decay, which raises the baseline p95 and loosens the limit slightly (min with the 4.0 cap still bounds it). Direction is toward looser, bounded by the cap. Non-blocking, worth a live look.
- `--sample` uses timeout 0 and tolerates not settling, which is intended.
