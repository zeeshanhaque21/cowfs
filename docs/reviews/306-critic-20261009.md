# Critic report: PR #306 (fix #301, read_atomic_across_chunk_boundary load-independent)

## Verdict

MERGE-AFTER-FIXES.
The atomicity proof is intact.
One small hang-guard gap should be closed first, and the PR body should state the runtime cost.

## Required fixes

1. Writer panic leaves readers spinning to CAP.
   Readers exit only on `stop` or `start.elapsed() < CAP`.
   `stop.store(true)` runs after the writer loop.
   `fs.write(..).unwrap()` or the `assert_eq!(n, BLOCK)` panics inside `thread::scope`, so `stop` is never set.
   The 3 readers then spin until CAP, now 120s (was 8s).
2. All-readers panic leaves the writer spinning to CAP.
   A `fs.read(..).unwrap()` panic in every reader means `reads` stops growing below MIN_READS.
   The writer then writes unbounded for 120s.
   One or two reader panics are fine because the survivors keep `reads` growing.
3. Recommended fix for both.
   Add a shared `AtomicBool failed`, set by a small drop guard (struct with `Drop` that stores true when `std::thread::panicking()`) in each spawned thread and in the writer.
   Both the writer condition and the reader loop check it.
   Cost: about 10 lines, and the hang guard then covers panics, not only starvation.
4. PR body omits the runtime cost.
   It says "about 23s" idle but does not say that is roughly 3x the old 8s cap.
   The old test was cut off by the 8s cap before finishing 4000 writes in the flush-every-write arm.
   The test now always completes the full 4000 writes plus the read target.
   Say so explicitly in the body.

## Checked, no finding

- Atomicity still proven.
  `torn == 0` is asserted first and unchanged.
  The torn detection code is unchanged (byte compare against all 8 versions).
  The `seen >= 2` check is unchanged.
  The final at-rest `read == versions[last]` is unchanged.
  `last` is still the last write issued before stop, and the writer stops early on torn only after the tear was recorded, so the torn assert fires before the at-rest check.
- Early stop on torn does not hide a tear.
  `torn` is monotone and asserted after the scope joins.
- Starvation distinction is real.
  The `reads >= MIN_READS` assertion can only fail when CAP is hit.
  Its message now says so.
  It is a tightened floor semantic (same 1000), not a weakening.
- Residual flake risk is low.
  `reads >= 1000` does not strictly guarantee one reader saw 2 versions.
  But the writer keeps writing for all those reads, and any two reads separated by a write differ.
- Memory growth is bounded in the test itself.
  `first_tear` uses `get_or_insert`, once.
  `kinds` is a fixed array.
  The store holds 8 content-addressed versions, so dedup should bound it.
  I did not measure store or journal growth over a 120s run in the flush-every-write arm.
  That is unverified.
- Ordering: Relaxed is correct.
  The counters are progress heuristics during the run.
  Final reads happen after `thread::scope` join, which gives happens-before.
  `fetch_max` on `seen` is also read after the join.
  SeqCst buys nothing.
- nextest.toml has no `slow-timeout` or `terminate-after` set, so 23s idle (and 120s worst case) triggers no kill.
  Only a default "SLOW" notice after 60s would appear.
  Under heavy parallel load the test could show SLOW, which is cosmetic.
- Mutant claim is plausible.
  A second-view back half makes every straddling read mixable, and 0.46s is consistent with early stop on torn.
  I could not re-run it (no edits allowed).
  Note it was run idle, and the loaded runs were on the unmutated source only.
- The 72 loaded runs and "min 20023 reads" claim is consistent with the new design.
  I did not re-run it.
  Label it as author-measured.
