## 2. List cannot waive an established regression; missing or malformed file is stricter

- The established-regression reason is appended at bench/pjdfstest.py:1183-1186, before and independent of accepted_reasons (line 1188). state_from (line 64) returns FAIL if any DIVERGENCE exists, so the list cannot remove it. The list only removes the new "not covered" DIVERGENCE.
- Missing file: load_accepted returns [] (line 1006), so nothing is waived. Stricter.
- Malformed JSON, missing "entries", or an entry lacking test, n, issue or reason raises (lines 1009-1013), so the run crashes instead of guessing. Top-level shape errors raise KeyError, not the ValueError the docstring implies, but it is still a hard stop.
- Test coverage: test_entry_without_a_reason_is_refused covers one malformed case. No test for missing "entries" or invalid JSON. Minor.

## 3. Entry derivation and the over-match question

- I re-derived the #108 set from the full run: cases whose cowfs raw stderr contains "pathconf returned -1" are exactly the 13 cases listed, and the worse positions in those cases are exactly the 69 #108 entries (set equality true). No native-arm stream contains the string.
- Every cowfs assertion that native passes in those 13 cases is already failing (for example mknod/03.t and unlink/03.t have zero cowfs-ok positions). So there is no further worse row in those cases that could slip in, and the selection does not over-match in the evidence.
- Keying is (test, n), not (case, n, issue). The issue field is a label used only for the disclosure counter (bench/pjdfstest.py:1024, 1025, 1034). It is not case-only (a position-level key), but it is also not issue-aware.
- Consequence I could demonstrate: I changed the failure text at unlink/14.t #4 to a different, unrelated error and accepted_reasons still waived it. A different real defect at an already-listed position is invisible, and a future real regression in any of the 13 #108 cases at a listed position is masked for as long as the pathconf problem keeps them failing. This is inherent to position keying and is the tradeoff of this design. Note it in the list reason or the docs.
- "Derived by code" is not reproducible from the repo: only a derived_from field exists in the JSON, and no script that regenerates the list is checked in. I reproduced the derivation with my own throwaway code. Ask for the derivation script or a one-line recipe, otherwise the next refresh is hand work.
- Wording: the JSON reasons are accurate (one distinct reason per issue). The 2 root-required mknod/03.t rows (positions 1 and 2, root_required True) are correctly inside the 69.

## 4. Rot check

- Stale entries (test compared in this run, position not worse) produce a COVERAGE reason, bench/pjdfstest.py:1034-1039. Entries for tests absent from the run are deliberately silent (test_entry_for_a_case_not_in_this_run_is_not_stale), so partial runs do not spam.
- Full-run check: zero stale entries (the evidence test asserts it). Sample run: reports "20 ... accepted divergences: {'#108': 20}" and no stale entry.
- Limit: stale is COVERAGE, which never changes the exit. So a fixed bug leaves a waiver that silently stays until someone reads the report. It cannot hide a new regression at other positions, because only currently-listed (test, n) keys are waived and a position only needs to be listed while it is worse. Acceptable, but a stale entry in a compared case could arguably be a FAIL. Suggestion, not a blocker.
