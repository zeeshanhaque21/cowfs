# Issue 164: writers_and_collects_at_once_lose_nothing NoSuchSnapshot

## CI evidence
Run 37848060864 (PR 163, ubuntu-latest), `cargo test --workspace`.
Line: `thread '<unnamed>' panicked at crates/cowfs-gc/tests/common/mod.rs:370:52: walk: NoSuchSnapshot`.
Parent: `race child must complete under the deadline: code=Some(101) timed_out=false waited=6426ms`.
The panic site is the test helper `Parts::live`, not the collector.
The rerun (run 37849831876) passed.

## Code reading
`Parts::live` listed durable snapshots, then `snapshot_by_id` (the lookup was already guarded), then `snap.live_blocks(..).expect("walk")`.
The remover thread in the same fixture calls `remove_snapshot` concurrently.
A removal landing between the lookup and `live_blocks` makes `live_blocks` return `NoSuchSnapshot`, and `expect` panics.
The gc mark pass had the same window and was already fixed in f501157 (issue 83).
The helper kept the unfixed twin of that window.
Classification: test race (an allowed outcome the test must tolerate), not a gc bug.

## Deterministic reproduction
Added `Parts::live_with(after_lookup)` and test `regressions.rs::live_helper_tolerates_a_snapshot_removed_between_lookup_and_walk`.
The hook removes the victim snapshot after its lookup and before its walk, no sleeps.
Before the fix: `panicked at common/mod.rs:381:52: walk: NoSuchSnapshot` (same message as CI).
After the fix: passes, and the kept snapshot's blocks stay in the live set.
Fix: `live_blocks` returning `NoSuchSnapshot` skips that snapshot; every other error still panics.

## Statistical loops (macOS, pre-fix binary, 1 test per run)
Idle, N=100: pass=100 fail=0.
Under load (16 busy perl processes, load average 44 to 70), N=100: pass=100 fail=0.
The natural race did not reproduce locally in 200 runs (0 failures).
The window is a few microseconds wide (between two metadata calls), so a 0/200 result bounds nothing; the deterministic hook reproduction above is the evidence.
No CI loop branch was pushed: the deterministic reproduction pins the exact panic, and the fix PR's own CI runs the real race on ubuntu.

## Verdict
Root cause class: test race in the test helper `Parts::live`, unfixed twin of the issue-83 window.
Race window: after `Meta::snapshot_by_id` returns and before `Snapshot::live_blocks` reads the root, a concurrent `remove_snapshot` from the remover thread.
Not a gc bug: the collector already skips a snapshot removed in its own window (f501157), and the fixture still fails on any other error.
