### Loop result

The test now lives in crates/cowfs-nfs/tests/resource_bounds.rs, not hardening.rs.
I ran `a_connection_flood_is_capped_and_the_server_recovers` 30 times from a prebuilt test binary, on the main 9874afa source, on this Mac (macOS, soft ulimit -n 1048576), with the other agents' normal load.
Result: N=30, 30 passed, 0 failed. No log contains "Bad file" or "code: 9".
I also ran the whole resource_bounds binary 3 times (7 tests each, all passed) and the whole hardening binary once (17 passed).
The sample is small and the machine has a very high fd limit, so this is weak evidence about low-limit hosts.
The do-nothing baseline is the already-merged code. The pre-74 harness failed at soft limits 128 through 768 per the verification doc, so the harness defect was real and is fixed.

### Recommendation for #57

Close it with this evidence.
The reported failure was a harness fd-budget defect (fixed by PR 74), the real server defect behind it was fixed by PR 93, and the literal errno 9 was never reproduced by anyone.
Reopen only if EBADF is seen again on a current main. Do not build a fix for an unreproduced failure.
