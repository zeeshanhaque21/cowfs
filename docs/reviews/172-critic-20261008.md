## 2. The enforce step is real

The test step uses `shell: bash`.
The log shows the effective shell is `/usr/bin/bash --noprofile --norc -e -o pipefail`, so a failing unittest fails the step through `| tee`.
The enforce step reads `namespaces.log`, which is the tee output of that step.
Each assertion can fail loudly:
- the marker string `a mount namespace was available` must be in the log, otherwise it asserts;
- the regex `^(test_\w+) \(test_namespaces\.Isolation\.\w+\) \.\.\. ok$` with MULTILINE is anchored on both ends and names the Isolation class, so a skip line or an error line cannot match, and the count must equal exactly 9;
- `^Ran 17 tests` and `^OK \(skipped=1\)$` must match;
- the list of skipped test names must equal exactly `["test_off_linux_is_unmeasurable"]`.
The step runs `python3 -` from a heredoc under `bash -e`, and an AssertionError exits 1.
It cannot pass vacuously: a missing or empty log raises in `read_text()` or fails the marker assertion, and an empty regex result fails the count of 9.
The marker string is printed by bench/test_namespaces.py line 119 only on the branch where the probe found a namespace.
Negative control run 37859015340 (push on branch probe/userns-neg-171, headSha 20f523c) failed only the step "Enforce that isolation ran, not skipped".
Its diff from the PR head is exactly three lines: the trigger branch, and the sysctl plus unshare lines replaced by `true`.
So the control is the same job without the sysctl and nothing else.
Its Namespace tests step passed with `OK (skipped=10)` and the reason `unshare: write failed /proc/self/uid_map: Operation not permitted`.
The enforce step then died with `AssertionError: helper reported no namespace: isolation skipped` and exit code 1.
That is the right reason at the right step.
In the control, the first assertion fires, so the count, skip and OK assertions are not exercised by a failing run.
They are simple and read correctly, but they have no negative evidence of their own.

## 3. The sysctl step

`sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0` is the right key for ubuntu-24.04.
The probe run 37857349491 printed the real values on kernel 6.17.0-1022-azure: apparmor_restrict_unprivileged_userns=1, unprivileged_userns_clone=1, user.max_user_namespaces=63838.
Before the change `unshare -Ur -m true` gave rc=1 with the uid_map error.
So `unprivileged_userns_clone` and `max_user_namespaces` are already permissive and need no change.
`sysctl -w` is runtime only and the runner VM is ephemeral, so there is no persistent effect and no write to /etc.
The step then runs `unshare --user --map-root-user --mount --propagation private -- true` under `bash -e`.
If the sysctl ever stops working, that step fails first with a clear error.
Risk: a future runner image could rename the key or ship a different restriction mechanism.
That fails loudly at the sysctl or unshare line, which is the desired behaviour.
