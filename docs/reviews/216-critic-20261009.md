## 2. Is the g2 bar meaningful

No, not as configured.

- The same edit varied from 1.37 s to 12.8 s (ctl) and 1.28 s to 6.96 s (core) in my 5 reps on the same host in the same minute.
  That is a 5x to 9x spread, against a bar that tests a 0.5 to 0.7 s margin.
- On macOS the g2 verdict is NOT a 1.5x ratio: it is `add < --budget-add` with default 1.0 s (`bench/compare.py:362-364`).
  The PR text and the task framing speak of 1.5x, but only Linux uses the ratio (`bench/compare.py:365-366`).
  A native median of 1.4 s with a 1.0 s allowance is a 1.7x ceiling on macOS and 1.5x (0.7 s) on Linux.
- The harness takes `--reps` per gate, default chosen by the caller (the doc plans 5), and `compare.py` uses medians (`median()`, `bench/compare.py:~333`) with a load ceiling of 30 and a 2x load-skew refusal (`LOAD_CEILING`, `LOAD_SKEW`).
  A load ceiling of 30 is far above a load of 11 to 17 that already gives a 9x spread, so the guard does not catch this regime.
- There is no minimum-duration guard and no minimum-added-seconds guard on the native median.
  `G2_MIN_UNITS` only guards the work shape (units and relinks), not the wall time.
- `--noise-floor` exists, but nothing forces the verdict to be UNMEASURABLE when the noise-floor ratio exceeds the bar margin.

Recommendation, concrete, not for this PR:

1. Follow-up issue: make g2 a bigger target.
   The widest realistic edit-rebuild is `cargo build --tests` (or `cargo test --no-run`) after the cowfs-vfs edit, which also rebuilds and relinks every test executable.
   I did not measure that, so label it unverified, but it multiplies the linked executables from 3 to dozens and moves native time well past 5 s.
   A `cowfs-vfs` edit plus `cargo build --workspace --all-targets` is the same idea with fewer flags to explain.
2. Add a native-duration guard in `compare.py`: g2 is UNMEASURABLE (not PASS or FAIL) when the native median is under a stated floor (suggest 3 s) or when native min to max spread exceeds the allowed margin.
3. Keep the macOS added-seconds budget and add the same absolute budget on Linux, or require at least 7 reps for g2 and compare medians with the noise-floor run.
4. Until then, do not quote a g2 PASS or FAIL from this workload as a gate result.

## 3. compare.py guard

Exercised the CLI with the scratch files.
All refused with rc 3 and an `INVALID` line on stderr, except the matching pair:

| Input | rc | Message |
| --- | --- | --- |
| both arms at new pin | 0 | none |
| cowfs arm at c1619ec | 3 | `meta corpus_sha 'c1619ec...' is not the current g1/g2 pin 3f4fba25...` |
| meta with no `corpus_sha` | 3 | `corpus_sha None is not the current ...` |
| `corpus_sha: null` | 3 | same |
| abbreviated sha `3f4fba2` | 3 | refused (strict equality) |
| file with no meta record | 3 | `rep before the meta record` |
| second meta record at the old pin appended | 3 | `more than one meta record` |
| old-pin native and cowfs | 3 | refused |
| good arms plus old-pin `--noise-floor` | 3 | refused |

The check is at `bench/compare.py:201-205` and runs for every file in `file_problems` including the noise floor.
It compares against the imported `gates.DEFAULT_SHA` constant, not the `COWFS_BENCH_CORPUS_SHA` env override, so setting the env while running compare cannot bypass it.
A missing field cannot slip through because `None != DEFAULT_SHA`.
Files written by a `COWFS_BENCH_CORPUS_SHA` override (`bench/gates.py:482`) are refused too, as the doc says.

## 4. Per-rep git checkout

- Command is `git -C <corpus> checkout --quiet -- crates/cowfs-vfs/src/lib.rs` (`bench/gates.py:305`).
- `self.corpus = root / "corpus"` (`bench/gates.py:183`), and `ensure_corpus` clones `--no-hardlinks` into it from `REPO` (`bench/gates.py:188-201`), so it is a separate clone, never the primary checkout.
- The pathspec is a single repo-relative file after `--`, so nothing outside that one file in the corpus clone can change.
- A dirty corpus is safe: other uncommitted files are untouched, and only the one edit file is reset, which is the intended behavior.
- It requires `.git` in the corpus, which `ensure_corpus` guarantees, and a tracked file at the pin, which holds at 3f4fba2.
- Residual: the reset runs inside the timed region, adding a git process (tens of ms natively, more through a FUSE or NFS mount) to every g2 rep.
  Moving the reset and the write before `t0` would need a small split of `g2()`, so file it as a follow-up.
