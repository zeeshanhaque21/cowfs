# Critic report: PR 229 (Fixes 221), g2 UNMEASURABLE rule, untimed prep, `cargo build --tests`

Verdict: PASS WITH NOTES.
Reviewed head ddd1ce5 (branch fix/g2-unmeasurable-221) in a scratch clone; the primary checkout was not touched.
Evidence labels: RAN means I executed it, READ means code inspection only.

## Findings, most important first

### N1 (medium): the spread bound does not make the macOS 1.0 s budget testable
bench/compare.py:89 sets G2_SPREAD_MAX 2.0 and bench/compare.py:368-381 applies it.
RAN: native reps [17.4, 20, 23, 26, 29.3] with cowfs equal to native plus 0.5 s returns `None` (judged), so compare prints PASS or FAIL.
The reps span 12 s while the macOS bar (bench/compare.py:384 onward, `--budget-add` 1.0 s) is a 1 s difference of medians.
The PR's own measured spread (1.69x at 23 s, docs table) is therefore admitted, and that is about 10 s of range against a 1 s budget.
The rule fixes the 1.4 s regime of PR 216 but still lets noise decide the verdict on the new 23 s workload.
Suggested follow-up (not a blocker for this issue): on macOS also require the arm range (or half-range) to be under the budget, or switch macOS to a ratio bar; Linux 1.5x on 23 s (11 s margin) is closer to the spread but still marginal.
The comment at bench/compare.py:80-89 still argues from the old 1.4 s workload ("33 percent margin"); with 23 s native the 1.0 s budget is a 4 percent margin, so that text is stale.

### N2 (low): G2_MIN_UNITS stays 3 with 127 units and 117 relinks
bench/gates.py G2_MIN_UNITS 3 (diff hunk near line 76) and bench/compare.py g2_problem (compare.py:253-263).
A rep that rebuilt 3 units and relinked 1 executable now passes validity although the real workload is about 127/117.
The PR documents this as "a floor on shape", which is honest, but it no longer catches a partial rebuild (for example a cache that skipped the test targets).
Suggest raising the floor to a fraction of the measured count once a quiet-host count exists.
Also `bins_relinked` now counts test executables; the name is misleading but harmless.

### N3 (low): exit 2 can hide a real FAIL on another gate
bench/compare.py:525-527 returns 2 whenever any gate is unmeasurable, even if `fails > 0` (a g1 FAIL line is printed but rc is 2).
Pre-existing behaviour, but this PR makes it much more likely (every g2 under 3 reps or 3 s).
Consumers that read only the rc (bench/g12_run.py:660-666 records `compare.py rc`) lose the FAIL.
Not introduced here; worth an issue.

### N4 (low): `--sample` runs (1 rep) are now always rc 2 for g2
bench/g12_run.py:689 defaults reps to 1 for samples and the new rule needs 3 reps per arm.
test_g12_run passes (604 tests OK), so the plumbing check still works, but a sample g2 can never print PASS.
Acceptable (a sample is never a gate result); mention in the docs if not already.

### N5 (info): the cowfs write latency of the edit is no longer measured
The edit write now happens in `g2_prep` (bench/gates.py:310-317) for both arms, so the cost of one small write through the mount is outside the timer.
It is symmetric and negligible against 23 s, so fairness holds.

## Checks requested

1. Untimed prep: PASS (READ plus RAN tests).
   `timed_rep` (bench/gates.py:539-546) runs `<gate>_prep` first, then starts the clock; `main` uses it at bench/gates.py:582; no other caller invokes `ctx.g2()` directly (grep of bench/ and scripts/).
   Both arms go through the same `main`, so the reset and the edit are untimed on native and on the cowfs mount alike; neither arm keeps a dentry or page-cache advantage the other loses.
   mtime still triggers the rebuild: the write is the last action before the timer, so the file mtime is newer than the fingerprint, and the content differs by a unique ns-stamped comment.
   The dry run in the docs (127 rebuilt, 117 relinked on every rep) shows the rebuild fires; `g2_rebuild_problem` still refuses a rep that did not rebuild the edited crate.
   The timer still includes the `rebuilt_units` JSON parse of stdout; that was already true before and is small.
2. UNMEASURABLE rule: PASS with N1 and N3.
   RAN: native median 2.99 s is refused, exactly 3.0 s is judged (strict `<`); a zero-second rep in an arm is refused through `lo <= 0` (cowfs [0,3,3] refused); native [3,6,3] is exactly 2.0x and admitted (`>` bound, inclusive).
   NaN, negative and non-finite `wall_s` never reach the rule: `file_problems` (compare.py:296) rejects them as INVALID rc 3.
   Missing reps and an empty arm: fewer than 3 reps gives UNMEASURABLE per arm (compare.py:371-373); a gate absent from one arm is a coverage gap before the rule.
   Different rep counts between arms are allowed, each arm needing >= 3; the ratio uses the zipped prefix, unchanged.
   Exit code 2 is the existing "unmeasurable" code (compare.py:527), distinct from 1 (FAIL) and 3 (INVALID); no collision.
   There is no flag or env bypass; the check sits after the load ceiling check and before `verdict`, for both the macOS budget and the Linux 1.5x path (verdict at compare.py:384-394 is only reached after it).
3. `--tests` workload: PASS.
   `cargo build --tests` compiles test binaries but does not run them, so socket-under-mount failures cannot occur in g2; the target dir is the harness's separate root, only sources are read from the mount.
   `warm_tests` is unconditional but cheap when current; it runs after `warm_target` (tested).
   Rep time about 16 to 23 s is acceptable: 5 reps per arm and two native runs is a few minutes total, far under the 7200 s command timeout (bench/gates.py:124-136).
   Not yet measured on the cowfs mount, as the docs say; that is the main residual risk (compile of 127 units reading sources through NFS or FUSE).

   Spread 2.0x is plausibly loose rather than tight: the PR's own load 50 to 212 data gave 1.69x, so a quiet host would not be refused (but see N1: loose relative to the 1 s budget).
