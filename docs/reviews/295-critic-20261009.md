## Does the diff do what the issue and body claim
Yes.
The issue asks for a failing-first test, a hash or CRC on mark.bin with discard on mismatch, backward compatibility where an old file is rebuilt and never trusted, and a decision on the other state files.
The diff adds a trailing 32-byte BLAKE3 hash over every preceding byte, including the magic, and bumps the magic to COWMARK4.
The old known-bug test is un-ignored and renamed, so it was the failing-first test.
The decision on atime.bin is stated and correct: it is only an ordering hint and never decides what is freed.

## Correctness
The hash is verified in parse() before any body byte is believed, and the parse is all-or-nothing as before.
A short file is handled: split_at_checked with saturating_sub gives an empty prefix and a short hash, and the hash.len() check rejects it.
An empty file hashes the empty slice and fails to match, so it is rejected.
A leading junk byte, trailing garbage, a truncation, a zeroed span and a bit flip all change the hashed region or the hash position, so they are rejected.
A COWMARK3 file is rejected because its last 32 bytes do not match the hash of the rest.
save() builds the buffer, appends the hash, and keeps the existing write to tmp, fsync and rename, so crash safety is unchanged.
blake3 is already a workspace dependency, and the Cargo.lock change is only the gc crate edge.

## Do the tests fail without the fix
The renamed power_collect test lost blocks on 58 of 64 seeds before the fix, per the PR body.
Without the hash, a_damaged_file_is_never_trusted fails on the bit flip and the zeroed span, since both parse as a valid set.
The existing malformed-file test now seals its mutated bodies, so it still exercises the structural checks and is not short-circuited by the hash.
The test checks that has_root is false, n_blocks is 0 and dropped is false for every damage case, plus a control that an intact file is reused.

## Claims check
The test counts in the PR body match the diff: state.rs goes from 14 to 15 and power_collect stays at 4.
The 58 of 64 figure is from the author's cachyos run and I could not verify it. It is plausible, and the test's own seed loop would reproduce it.

## Findings
1. Nit: the doc comment at crates/cowfs-gc/src/state.rs line 20 still opens with "COWMARK3 records which blocks belong to which walked root". It is historically accurate and the COWMARK4 paragraph follows, but it could say COWMARK4 for the current format. Not blocking.
2. Residual, by design: a corrupt file is not deleted on load. It stays on disk until the next save overwrites it. This is harmless because every load re-rejects it.
3. Residual, by design: the hash protects the cache file only. Corruption of store blocks or snapshot metadata is out of scope for issue 288.

## Risk

The worst case of the change is one full walk after upgrade, which the docs state accurately.
No scope creep: the diff is the format change, its tests, and docs.
