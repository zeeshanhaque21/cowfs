## 1. Scratch directory swap between mkdirat and open

Safe against a different uid.
`mkdirat(dir, scratch, 0700)` then `openat(dir, scratch, O_RDONLY|O_DIRECTORY|O_NOFOLLOW)`.
The uid and mode check runs on `fstat` of the opened fd, not on the path.
A swapped-in directory made by the attacker is owned by the attacker, so `st.uid != geteuid()` refuses it.
A symlink is refused by O_NOFOLLOW, a non-directory by O_DIRECTORY.
An attacker cannot create a directory owned by this uid, so the check cannot be spoofed.
A default ACL on the parent with named entries does not weaken it: the group bits (the ACL mask) are 0 for a 0700 request, so `mode & 0o077 == 0` still holds and named users are masked out.
Same-uid or root attackers are out of the boundary, as the PR body says.

## 2. Cleanup after the attacker renames or removes the scratch directory

Node cleanup is `unlinkat(sd_fd, "n")`, relative to the held fd. It cannot reach anything outside the scratch directory.
Scratch cleanup is `unlinkat(parent_fd, scratch, AT_REMOVEDIR)`, by name. It can only remove an empty directory. Worst case it removes an attacker-substituted empty directory. It never chmods anything.
No path found that deletes or chmods something else.

Finding A (low): `made.and(removed)` lets a failed rmdir override a successful rename-out.
If the attacker renames the scratch directory away after the rename-out, `unlinkat` gives ENOENT, `mknod` returns an error, but the node already exists at the target name and is not registered.
Only reachable by an attacker with write access to the parent, who can already do worse there.
Fix: when `made` is Ok, ignore (or log) the rmdir error. Return the rmdir error only to report the leak, never as an operation failure.

## 3. Parent held by fd or re-resolved

Held by fd.
`mkdirat`, `openat`, `renameat(sd, NODE, dir, name, true)` and the final `unlinkat` all use `dir.file.as_fd()`, the already-open parent descriptor.
No path is re-resolved, so there is no parent TOCTOU inside this function.
Residual, pre-existing and unchanged: after the rename-out, `fstatat(dir, name)` and `register` go by name. A same-name swap there would be registered with the swapped node's attributes.
This is not a chmod and is outside #211, but the PR's wording "never a swapped-in one" is about the chmod only.

## 4. Leak on crash (#307)

Documented in the doc comment and the PR body, and filed as #307.
Stray `.cowfs-mknod-<32 hex>` directories are listed by readdir (no filter found in lib.rs) and are permanent.
A concurrent readdir or lookup by an NFS client during the window can also see a live scratch directory.
Acceptable for this PR. #307 should include a startup sweep of empty `.cowfs-mknod-*` directories owned by this uid.

## 5. getrandom(2)

Flags 0 is right: blocking only before the pool is initialised.
Short read: not possible for 16 bytes. The code checks `n == 16` and maps anything else to EIO, so it is correct anyway.
Finding B (nit): no EINTR retry. Per man page, EINTR is possible only before the pool is initialised (early boot). One-line retry loop is cheap.
ENOSYS on kernels before 3.17 surfaces as an error from mknod. Fine for the targets.

## 6. Error mapping, tests, PR body

- EEXIST from RENAME_NOREPLACE reaches the caller as EEXIST. Unit test `mknod_private_sets_the_mode_and_removes_its_scratch_directory` checks this and that no scratch directory is left.
- EINVAL/ENOSYS from the rename becomes ENOTSUP. The mapping wraps only the rename call, so a chmod_fd EINVAL is not mislabelled. Good.
- Identity mismatch and owner mismatch both give EIO. They cannot be told apart by callers. Fine, but the doc could say so.
- The owner check uses `geteuid`. No `setfsuid`/`setresuid` exists in the crates, so no mismatch today. On an idmapped mount or an all_squash NFS backing store, the check would fail with EIO on every call. Worth one line in the doc comment.
- ACL test strictness: `set_default_acl` asserts when `CI` is set and setfacl or getfacl is missing or the ACL does not list back. CI run passed, so it ran for real on ubuntu. Local runs without setfacl skip. Good.
- Race test termination: runs at least 20000 rounds, then continues until 500 swaps or 60 s, then asserts swaps >= 500. Terminates. Flake risk is low: it needs a starved helper thread for the full 60 s. Acceptable.
- Test gap: the race test never checks that no `.cowfs-mknod-*` directory is left after the loop. A leak under contention (for example EEXIST paths) would go unseen. Suggest asserting the parent has no such entries after `race(true)`.
- Test gap, stated honestly in the PR body: no second-uid actor test. The body says so.
- PR body is honest: it does not claim a second-uid test, states Linux-only, /proc and RENAME_NOREPLACE requirements, and the #307 leak.
