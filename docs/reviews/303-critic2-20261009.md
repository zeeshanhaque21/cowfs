# Critic round 2: PR #303 (fix #211, head 0788eee)

Verdict: MERGE-AFTER-FIXES.
The target-name swap is closed and the code is fail-closed on the random read.
The remaining gaps are an overclaimed temp-name guard, a wrong ENOTSUP claim for missing /proc, and a test that can skip silently in CI.
Review was static (diff reading) only; nothing was run, no live mount touched.

## F-by-F

### Random name (OK)
`File::open("/dev/urandom")?.read_exact(&mut rnd)?` returns an error on open failure and on a short read (UnexpectedEof).
There is no fallback to a predictable name, so it fails closed.
Nit: the open fails inside a chroot or container without /dev/urandom, and mknod then returns ENOENT with no hint. The `getrandom(2)` syscall is simpler and has no fd.
Nit: the error from this step is not mapped, so the caller sees a bare ENOENT or EIO that looks like a target-name error.

### Identity check (weak, finding 1)
After `mknodat` the code opens the temp name O_PATH|O_NOFOLLOW and runs `fstat` on the fd, then checks type and `nlink == 1` (`made_node`).
It does not compare dev/ino with anything, and cannot: there is no `fstatat` before the open, so nothing records what `mknodat` made.
An fstatat before and after would not help either, because the swap can land before the first fstatat.
The check is a type and link-count filter, not an identity check.

### Residual TOCTOU between mknodat and openat (exploitable, low to medium, finding 1)
The temp name is not secret. Any process that can write the directory can `readdir` and see `.cowfs-mknod-<hex>`, so the 128 bits only stop blind guessing.
The attacker needs only directory write, the same power the original #211 attacker had.
A hard link of a victim is refused: linking raises nlink to 2.
A rename of the victim itself onto the temp name is accepted: same type, nlink stays 1, so `made_node` passes.
This needs the victim to be a fifo, socket or device node on the same filesystem, with the attacker able to write the victim's parent directory.
Then `chmod_fd` via `/proc/self/fd` chmods the victim (follows the magic link to the inode) to the mode the caller asked for, and the rename then moves the victim into the target name.
Effect: an attacker with dir-write but no ownership gets a chmod on, and a move of, a special node it does not own. The daemon is usually root, so ownership does not stop it.
The window is a few microseconds, but the attacker can spin on readdir, as the existing race tests do.
Impact is bounded by the type match: regular files and directories are not reachable.
Robust fix: `mkdirat` a random 0700 scratch directory in the target dir, `mknodat` and chmod inside it, then `renameat2(NOREPLACE)` out and `rmdir`. Nobody else can enter it, so no identity question remains.
A default ACL cannot widen a 0700 mkdir, because the mask comes from the group bits.
Cheaper alternative: keep the temp name and accept the residual, but then the docs must say so (finding 4).

### Cleanup on failure (nit)
When `made_node` refuses, `unlinkat(tmp)` removes whatever sits there, which may be the attacker's renamed-in victim.
That is the same power the attacker already had (he moved it), so low risk. Note it in a comment.

### EINVAL/ENOSYS to ENOTSUP (partially wrong, finding 2)
The `map_err` wraps the whole chain: openat, fstat, `chmod_fd` and renameat.
Only renameat2 returning EINVAL (no RENAME_NOREPLACE support) or ENOSYS justifies ENOTSUP.
EINVAL from the other steps is also relabelled ENOTSUP, which hides real errors.
`mknodat` itself is outside the map, so its EINVAL passes through unmapped. That is inconsistent but correct.
The doc says missing /proc fails with ENOTSUP. It does not: `chmod("/proc/self/fd/N")` fails with ENOENT (or EACCES under hidepid), and nothing maps that.
Fix: map only the renameat step, and probe /proc once (or map ENOENT from `chmod_fd`) to ENOTSUP, or correct the doc.

### ACL test strictness (finding 3)
The CI guard asserts only that `setfacl` succeeded.
The `getfacl` check runs after the assert, and its result only feeds the return value.
If `getfacl` is missing, or the output does not contain `default:user::rwx`, the test prints SKIP and passes in CI.
Move the getfacl check into the CI assertion, or assert the xattr `system.posix_acl_default` directly.
The ACL `u::rwx,g::r-x,o::r-x` with a 0600 request does not change the requested mode, so the test proves the path is taken (via `mode_may_change`), not that the kernel altered a mode.
That is acceptable, but the doc comment says the kernel "may change the mode", which is true but untested.

### Race test min-swap assertion (finding 5)
`swaps >= 500` guards against a starved helper, which is good, but it counts swaps, not swaps that overlapped the mknodat to chmod window.
It can still go green with zero overlap.
It can also flake on a starved CI box: the helper stops as soon as the 20k main loop ends, and each main iteration is only a few syscalls.
Better: have the main loop run until the helper reaches N swaps (with a time cap), then assert.
The test does not exercise the temp name at all, as the PR admits. The finding-1 attack has no coverage.
The helper's `unwrap()` on rename or symlink is fine; panics surface via `join().expect`.
Side effect: 100k decoy sockets in `side` per run; cleanup is via `force_remove_dir_all`, fine.

### PR body honesty (finding 4)
"This closes the swap at the target name": true.
"A process that knows the random name could still race the temp name, but the type and nlink check refuses a hard link or other type there": overclaimed.
The name is visible to `readdir`, so "knows" is trivial.
A same-type nlink-1 node renamed in passes the check, and is then chmod'ed.
Proposed wording: "temp name is guarded by a type and link-count check only. A same-type, single-link node renamed onto the temp name between mknodat and open is accepted and chmod'ed. Tracked in follow-up #N."
"needs /proc ... maps to ENOTSUP": wrong for /proc, as above.
The mknod behavior change on macOS (now ENOTSUP) is disclosed, which is good.

## Findings, ranked
1. Same-type nlink-1 node renamed onto the temp name is accepted, then chmod'ed and moved in. Use a private 0700 scratch dir, or document and file a follow-up. Docs must stop claiming a guard.
2. ENOTSUP mapping too broad (all steps) and missing-/proc maps to ENOENT, not ENOTSUP as documented.
3. ACL test can silently skip in CI when getfacl is missing or its output differs. Move the getfacl check under the CI assertion.
4. PR body and `mknod_private` doc overclaim the temp-name guard. Reword.
5. Min-swap assertion counts swaps, not overlaps. It can flake on a starved box. Run until N swaps or a time cap.
6. Nits: use `getrandom` instead of /dev/urandom, comment on the failure-path unlink, no test injects a node at the temp name (no seam).

## Merge conditions
Findings 2, 3 and 4 are small and must land.
Finding 1 must either be fixed with the scratch-dir approach or be explicitly documented with a filed follow-up issue number in the PR body.
Finding 5 is recommended.
