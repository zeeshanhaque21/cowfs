## 3. Policy correctness and siblings

Fix: `if name == b".." { return Err(NFS3ERR_NOTEMPTY); }` placed after `not_side(d)?` and before `check_name`.
Matches pjdfstest rmdir/12.t #4 (ENOTEMPTY or EEXIST for `..`) and keeps `.` at EINVAL.
Ordering is sound: sidecar directory ids still answer NOTDIR first, so the guard cannot mask that.
It returns before `with_names`, `translating`, and `vfs.rmdir`, so no lock, barrier, or purge is skipped; there is no state to owe.
Other `check_name` callers in the adapter: lookup (line ~399, `.` and `..` are handled by explicit arms before), `remove` (743), `rename` (833/834), plus `new_name` (create paths, EXIST for `.`/`..`, correct).
Sibling `remove` of `..` and `rename` from or onto `.` or `..` still answer EINVAL.
Linux answers other codes there: `do_unlinkat` returns EISDIR for non-LAST_NORM (namei.c:4511-4513, v6.12) and `do_renameat2` returns EBUSY for old or new non-LAST_NORM (namei.c:5090-5098).
These are the same root cause (blanket `validate_name` EINVAL) but not in scope for 109: the issue and the pjdfstest closure cover only rmdir/12.t.
No pjdfstest test in the recorded closure asserts them. Recommend a follow-up issue only if a wider pjdfstest run reports them. Not blocking.

## 4. FUSE needs no guard

FUSE adapter `crates/cowfs-fuse/src/fs.rs` rmdir (line 663) does `name(&n)` first, and `name` is `validate_name(...).map_err(|e| e.errno())`, so a `..` reaching it would be EINVAL (fs.rs:1053 asserts that).
Whether it can reach it: VERIFIED against Linux v6.12 `fs/namei.c` `do_rmdir`, fetched from raw.githubusercontent.com: after `filename_parentat`, `switch (type) { case LAST_DOTDOT: error = -ENOTEMPTY; goto exit2; case LAST_DOT: error = -EINVAL; goto exit2; ...`.
So the kernel answers before calling the filesystem, and the FUSE path never sees `..` or `.` from rmdir(2).
A non-kernel FUSE client (libfuse low-level user) could still send it, but that is outside the supported surface.
Claim holds. Residual: `linux-fuse` CI does not prove it either; it rests on the kernel source.
